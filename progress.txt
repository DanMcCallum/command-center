# Progress Log

## Learnings
(Patterns discovered during implementation)
- Dashboard has no `typecheck` npm script — run `npx tsc --noEmit` from `dashboard/` (passes clean).
- Platform keys are canonical in `config/ad-platforms.json`; `config/posting-platforms.json` must keep the same six keys (landmodo, land_century, landflip, land_com, land_listings, landhub).
- Config JSON files use a top-level `"_doc"` string + `"platforms"` object — follow that convention for new config files.
- login_url/new_listing_url for all platforms are best-effort placeholders; verify against live sites during US-005/US-006 selector discovery.
- Port 3000 runs the PRODUCTION dashboard (`npm start` via @reboot cron) serving stale compiled code — don't test API changes against it and don't restart it. Spin up `npx next dev -p 3001` for live verification, then kill it.
- No test framework in dashboard/ — verify API routes by curling a temp dev server (create temp task → exercise → DELETE it).
- `updateTask` in dashboard/lib/data.ts merges `Partial<Task>` via spread, so any new optional Task field (like `postings`) is automatically persistable via PATCH with full-array-replace semantics — no data-layer change needed.
- Careful with `pgrep -f`: the pattern matches the checking shell's own command line; use a character class (e.g. `-p 300[1]`) to avoid self-matches.
