## Iteration 2 - US-002: Agent token auth helper
- Created dashboard/lib/agent-auth.ts exporting
  requireAgentToken(request): NextResponse | null (null = authorized).
  Reads AGENT_TOKEN via process.env with the root-.env.local fallback
  (readProjectEnvVar copied from lib/capture-server.ts — PROJECT_ROOT is
  path.resolve(process.cwd(), '..'), so it depends on the dashboard running
  from dashboard/). 503 when AGENT_TOKEN unset (fail closed), 401 on
  missing/wrong Bearer token, timing-safe compare over sha256 digests of
  both sides (fixed length, so timingSafeEqual can't throw and token length
  isn't observable).
- Files changed: dashboard/lib/agent-auth.ts (new)
- Verified: `npx tsc --noEmit` in dashboard/ exits 0; runtime check via a
  throwaway tsx script constructing Request objects: unset→503, wrong→401,
  missing header→401, correct→null, 401 body = {"error":"Unauthorized"}.
- Learnings for future iterations:
  - tsx scripts in /tmp compile as CJS: no top-level await (wrap in async
    main), and relative imports resolve from the script file — use absolute
    paths to import dashboard modules.
  - NextResponse works fine outside a Next server (it's a Response
    subclass), so route guards are unit-testable with plain Request objects.
  - Root .env.local has NO AGENT_TOKEN yet — US-004's curl verification
    needs the operator (or the iteration) to add one first; add it as
    AGENT_TOKEN=<random hex> to /home/mazer/claude/command-center/.env.local.

## Iteration 3 - US-003: Publish endpoint
- Added POST /api/tasks/[id]/publish
  (dashboard/app/api/tasks/[id]/publish/route.ts): validates {platform} body,
  400 on unknown/disabled platform (config read the same way as
  posting-platforms/route.ts: path.resolve(cwd, '..', 'config', ...)),
  404 unknown task, 409 when that platform's posting is queued/posting/
  awaiting_auth, otherwise REPLACES the entry with exactly
  {platform, status:'queued', attempts: prev+1, queuedAt: now} (stale
  lastError/listingUrl/screenshotPath intentionally dropped per spec),
  preserving other platforms' entries. Returns the full updated task.
- Added mutateTask(id, mutate) to dashboard/lib/data.ts: atomic
  read-modify-write of one task under the existing serialize() mutex;
  mutate returns Task or null-to-reject; result is a discriminated union
  {outcome: 'updated'|'rejected'|'not_found'}. Protects id/createdAt and
  stamps updatedAt like updateTask. **US-005 (claim) should reuse this** —
  its queued→posting flip with 409-if-not-queued is the same shape
  (capture the conflict reason in a closure variable, as publish does).
- Files changed: dashboard/lib/data.ts,
  dashboard/app/api/tasks/[id]/publish/route.ts (new)
- Verified: `npx tsc --noEmit` exits 0; hermetic runtime test exercised all
  criteria (400/404/409 paths, replace-not-merge, attempts prev+1, other
  platforms preserved, posted/failed re-publish allowed).
- Learnings for future iterations:
  - Route handlers are runtime-testable WITHOUT a dev server and WITHOUT
    touching the real tasks.json: build a sandbox dir with config/ and
    dashboard/data/tasks.json, process.chdir() into sandbox/dashboard
    BEFORE dynamically importing the route module (data.ts and config
    paths are computed at import time from cwd), then call the exported
    handler with a plain Request + {params: Promise.resolve({id})}.
    Run with `npx tsx --tsconfig dashboard/tsconfig.json <script>` so the
    '@/lib/*' path alias resolves.
  - updateTask() is NOT safe for postings changes (check-then-write races
    with the poster/other requests); always go through mutateTask.

- Files changed: dashboard/app/api/publish-jobs/claim/route.ts (new)
- Verified: npx tsc --noEmit exits 0. Curl against npx next dev -p 3001 with
  a throwaway completed task (one queued landflip + one posted landmodo
  posting): no/wrong token -> 401, bad body -> 400, first claim -> 200 with
  full task showing landflip status 'posting' (attempts untouched), second
  identical claim -> 409, claiming the posted platform -> 409, claiming a
  platform with no entry -> 409, unknown task -> 404; persisted state
  confirmed via GET, task deleted after.
- Learnings for future iterations:
  - Claim does NOT touch attempts (publish already incremented at queue
    time) and does NOT call recordAgentSeen (spec ties lastSeenAt to the
    US-004 poll only).
  - Killing the background dev server: a plain kill of the nohup pid leaves
    a detached next-server child holding port 3001 — use
    pkill -9 -f "next dev -p 3001" and re-check with curl. Do NOT pkill
    "next-server" broadly; the production dashboard on :3000 is also Next
    (it survived this time, but don't rely on it).

## Iteration 6 - US-006: Publish bundle endpoint (ad copy + photo list)
- Added GET /api/tasks/[id]/publish-bundle?platform=<key>
  (dashboard/app/api/tasks/[id]/publish-bundle/route.ts): requireAgentToken
  guard, 400 on missing platform or platform not matching /^[a-z0-9_]+$/
  (path-traversal guard — platform becomes a filename), 404 unknown task,
  404 with a clear message when outputs/<id>/<platform>.md is missing,
  otherwise {adCopy: <file contents>, photos: [sorted repo-relative
  workers/workspace/outputs/<id>/photos/* paths]}. Missing/empty photos
  dir -> photos: [] (readdir failure swallowed).
- /api/files/[...path] GET was completely unauthenticated, so per the spec's
  conditional criterion I added a NON-BREAKING token check: only when an
  Authorization header is present, requireAgentToken must pass (401/503
  otherwise); requests with no header (dashboard <img>, FileEditorModal)
  behave exactly as before. PUT untouched.
- Files changed: dashboard/app/api/tasks/[id]/publish-bundle/route.ts (new),
  dashboard/app/api/files/[...path]/route.ts
- Verified: npx tsc --noEmit exits 0 (run after both changes). Curl against
  npx next dev -p 3001 using real tasks (no throwaway data needed):
  no/wrong token -> 401; missing platform -> 400; platform=..%2F.. -> 400;
  unknown task -> 404; platform with no ad file -> 404 with the outputs path
  in the message; task-1783741999340-sfsooi landmodo -> 200 with full ad copy
  + 15 sorted photo paths; first photo path fetched through
  /api/files/<path> with the token -> 200 image/png (verified PNG on disk),
  with no header -> 200 (dashboard unbroken), wrong token -> 401;
  task-1783741270364-bo28kt (live, ads but no photos dir) -> photos: [].
- Learnings for future iterations:
  - Outputs dirs outlive tasks: task-1780891259218-ppunbv has full outputs
    but is deleted from tasks.json. When picking a real task for curl tests,
    cross-reference tasks.json with outputs/ first.
  - Do NOT kill the dev server with pkill -f "next dev -p 3001" from a Bash
    tool call — the pattern matches the calling shell's own command line and
    kills it mid-script (and may leave the server running). Use
    `fuser -k 3001/tcp` instead; it also can't touch production on :3000.
  - dashboard/app/api/tasks/[id]/ contains stray task-* DIRECTORIES (route
    dirs with task-id names, from some earlier accident). Harmless but
    surprising in ls output; don't mistake them for real routes.

## Iteration 7 - US-007: Proof screenshot upload (agent API)
- Added POST /api/tasks/[id]/proof?platform=<key>
  (dashboard/app/api/tasks/[id]/proof/route.ts): requireAgentToken guard,
  400 on missing platform or platform not matching /^[a-z0-9_]+$/ (same
  path-traversal guard as publish-bundle), 404 unknown task, 400 when the
  body doesn't start with the 8-byte PNG signature, belt-and-suspenders
  path.resolve check that the target stays inside postings/, then
  mkdir -p postings/ and write <platform>.png. Returns {path, size} with
  the repo-relative path (servable via /api/files like screenshotPath).
- No enabled-platform config check (matches the old poster, which wrote
  whatever platform script ran; the platform key only becomes a filename).
- Files changed: dashboard/app/api/tasks/[id]/proof/route.ts (new)
- Verified: npx tsc --noEmit exits 0. Curl against npx next dev -p 3001
  using real task task-1783741999340-sfsooi and one of its photo PNGs:
  no/wrong token -> 401, missing platform -> 400, platform=..%2F.. -> 400,
  unknown task -> 404, text body -> 400 with PNG-signature message,
  real PNG --data-binary -> 200; file on disk verified with `file` (PNG
  1086x1448) and `cmp` (byte-identical to source). Test postings/ dir
  removed afterward so no test artifact lingers in outputs/.
- Learnings for future iterations:
  - request.arrayBuffer() handles multi-MB raw bodies in App Router with
    no route config (2.6 MB PNG worked out of the box), same as formData
    did for photos.
  - PNG magic is the full 8 bytes 89 50 4E 47 0D 0A 1A 0A — check all 8,
    not just "starts with 0x89PNG".
  - fuser -k 3001/tcp remains the safe dev-server kill (iteration 6
    learning confirmed again).
