## Iteration 2 - US-002: Agent token auth helper
- Created dashboard/lib/agent-auth.ts exporting
  requireAgentToken(request): NextResponse | null (null = authorized).
  Reads AGENT_TOKEN via process.env with the root-.env.local fallback
  (readProjectEnvVar copied from lib/capture-server.ts — PROJECT_ROOT is
  path.resolve(process.cwd(), '..'), so it depends on the dashboard running
  from dashboard/). 503 when AGENT_TOKEN unset (fail closed), 401 on
  missing/wrong Bearer token, timing-safe compare over sha256 digests of
  both sides (fixed length, so timingSafeEqual can't throw and token length
  isn't observable).
- Files changed: dashboard/lib/agent-auth.ts (new)
- Verified: `npx tsc --noEmit` in dashboard/ exits 0; runtime check via a
  throwaway tsx script constructing Request objects: unset→503, wrong→401,
  missing header→401, correct→null, 401 body = {"error":"Unauthorized"}.
- Learnings for future iterations:
  - tsx scripts in /tmp compile as CJS: no top-level await (wrap in async
    main), and relative imports resolve from the script file — use absolute
    paths to import dashboard modules.
  - NextResponse works fine outside a Next server (it's a Response
    subclass), so route guards are unit-testable with plain Request objects.
  - Root .env.local has NO AGENT_TOKEN yet — US-004's curl verification
    needs the operator (or the iteration) to add one first; add it as
    AGENT_TOKEN=<random hex> to /home/mazer/claude/command-center/.env.local.
  - US-004..US-007 usage pattern: `const denied = requireAgentToken(request);
    if (denied) return denied;`

## Iteration 3 - US-003: Publish endpoint
- Added POST /api/tasks/[id]/publish
  (dashboard/app/api/tasks/[id]/publish/route.ts): validates {platform} body,
  400 on unknown/disabled platform (config read the same way as
  posting-platforms/route.ts: path.resolve(cwd, '..', 'config', ...)),
  404 unknown task, 409 when that platform's posting is queued/posting/
  awaiting_auth, otherwise REPLACES the entry with exactly
  {platform, status:'queued', attempts: prev+1, queuedAt: now} (stale
  lastError/listingUrl/screenshotPath intentionally dropped per spec),
  preserving other platforms' entries. Returns the full updated task.
- Added mutateTask(id, mutate) to dashboard/lib/data.ts: atomic
  read-modify-write of one task under the existing serialize() mutex;
  mutate returns Task or null-to-reject; result is a discriminated union
  {outcome: 'updated'|'rejected'|'not_found'}. Protects id/createdAt and
  stamps updatedAt like updateTask. **US-005 (claim) should reuse this** —
  its queued→posting flip with 409-if-not-queued is the same shape
  (capture the conflict reason in a closure variable, as publish does).
- Files changed: dashboard/lib/data.ts,
  dashboard/app/api/tasks/[id]/publish/route.ts (new)
- Verified: `npx tsc --noEmit` exits 0; hermetic runtime test exercised all
  criteria (400/404/409 paths, replace-not-merge, attempts prev+1, other
  platforms preserved, posted/failed re-publish allowed).
- Learnings for future iterations:
  - Route handlers are runtime-testable WITHOUT a dev server and WITHOUT
    touching the real tasks.json: build a sandbox dir with config/ and
    dashboard/data/tasks.json, process.chdir() into sandbox/dashboard
    BEFORE dynamically importing the route module (data.ts and config
    paths are computed at import time from cwd), then call the exported
    handler with a plain Request + {params: Promise.resolve({id})}.
    Run with `npx tsx --tsconfig dashboard/tsconfig.json <script>` so the
    '@/lib/*' path alias resolves.
  - updateTask() is NOT safe for postings changes (check-then-write races
    with the poster/other requests); always go through mutateTask.

  dashboard/lib/data.ts, dashboard/lib/types.ts, .gitignore
- Verified: npx tsc --noEmit exits 0. Curl against `npx next dev -p 3001`:
  no token → 401, wrong token → 401, correct token → 200 {"jobs":[]};
