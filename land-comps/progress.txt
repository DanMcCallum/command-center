## US-002: YAML config loading into a validated Settings model (2026-09-25)

- `config.py` defines one pydantic v2 `BaseModel` per PRD section (`SearchConfig`, `ScoringConfig` plus nested `TierFloors`, `ApifyConfig`, `CountyConfig`, `RegridConfig`) plus a `Secrets` `pydantic-settings` `BaseSettings` (env, with `.env` fallback via `env_file=".env"`) and a top-level `Settings` that nests them all. `load_settings(path="config.yaml")` reads YAML with `pyyaml` and validates via `Settings.model_validate`.
- Cross-field checks live as `model_validator(mode="after")` on the section they belong to (e.g. `acreage_ratio_min <= acreage_ratio_max` on `SearchConfig`), so error messages name the offending fields directly. `max_radius_mi`'s hard 5-mile ceiling and `red_flag_policy`'s `warn|reject` set are enforced by plain `Field(le=5)` and `Literal` constraints, which pydantic already reports clearly by field path.
- `county.fips` is typed `str` with a `field_validator` requiring digits only, so `config.example.yaml` must quote `"08093"`: an unquoted `08093` is ambiguous under PyYAML's YAML 1.1 int resolver and better avoided entirely.
- Added `pydantic`, `pydantic-settings`, `pyyaml` as runtime deps and `types-PyYAML` as a dev dep via `uv add` (updates `pyproject.toml` and `uv.lock` together rather than hand-editing).
- `config.yaml` (the operator's live copy) is gitignored; `config.example.yaml` at the project root is committed with placeholder actor IDs, county paths, vacant-land codes, and excluded deed types per the PRD's US-002 "unconfirmed operator prerequisite" note.

## US-003 + US-004: domain models, SQLite schema, geo and normalization helpers (2026-09-25)

- `models.py`: `Parcel`, `Candidate` (`status: Literal["sold", "active", "pending"]`), and the Jev result shape from PRD section 5 as three small typed answer classes (`NoulAnswer` for true/false judgments, `ScoreAnswer` for the 4-level 0-3 similarity scores plus the level `legend` Jev saw, `ChoiceAnswer` for `quality_tier`), composed into `JevAnswers` (7 fields, one per question) and `CompResult`. `CompResult`'s fields match the PRD's literal `score()` return sketch exactly (`composite`, `tier`, `gates_triggered`, `answers`) rather than also embedding `candidate`/`features`, since the PRD shows those as separate `score()` arguments, not `CompResult` members.
- `db.py`: `init_db(path) -> sqlite3.Connection` runs one `executescript` of `CREATE TABLE IF NOT EXISTS` statements for all 7 PRD tables plus two supporting indexes (`county_sales(lat, lon)` for the US-009 bounding-box prefilter, `run_results(run_id)`). `source_cache`/`jev_cache` columns are exactly as specified; `candidates` is a normalized-candidate store keyed `UNIQUE(source, source_id)` (distinct from `source_cache`'s raw-payload blobs), and `runs`/`run_results` are shaped for what US-019/US-020 will need to persist and reload a ranked run without re-scoring.
- `geo.py`: `haversine_miles` (standard great-circle formula, R=3958.7613 mi) and `acreage_ratio` (candidate/subject, `None` if either input is `None` or `0`).
- `normalize.py`: `normalize_apn(raw, county_fips, apn_length)` strips non-alphanumerics and zero-pads; takes `apn_length` as a required explicit arg rather than loading `Settings` internally, so it stays a pure function (callers pass `settings.county.apn_length`). `normalize_address` upper-cases, strips `.`/`,`, maps `#` to a `UNIT` token, and canonicalizes suffix/unit words via lookup tables. `looks_like_apn` treats any 2+-letter word as proof of a street name/suffix (i.e. not an APN); everything else composed only of digits/letters/dashes/dots/spaces, with at least one digit, counts as an APN.
- Added `tests/test_db.py`, `tests/test_geo.py`, `tests/test_normalize.py`, `tests/test_models.py` (36 tests total across the repo). The haversine test pins to the standard published Nashville->LA worked example (2887.26 km / 1794.06 mi) rather than a self-derived value, so it can't be tautological.
- All three gates green: `ruff check .`, `mypy --strict src`, `pytest -q` (36 passed).
