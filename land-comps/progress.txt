## US-002: YAML config loading into a validated Settings model (2026-09-25)

- `config.py` defines one pydantic v2 `BaseModel` per PRD section (`SearchConfig`, `ScoringConfig` plus nested `TierFloors`, `ApifyConfig`, `CountyConfig`, `RegridConfig`) plus a `Secrets` `pydantic-settings` `BaseSettings` (env, with `.env` fallback via `env_file=".env"`) and a top-level `Settings` that nests them all. `load_settings(path="config.yaml")` reads YAML with `pyyaml` and validates via `Settings.model_validate`.

## US-003 + US-004: domain models, SQLite schema, geo and normalization helpers (2026-09-25)

- `models.py`: `Parcel`, `Candidate` (`status: Literal["sold", "active", "pending"]`), and the Jev result shape from PRD section 5 as three small typed answer classes (`NoulAnswer` for true/false judgments, `ScoreAnswer` for the 4-level 0-3 similarity scores plus the level `legend` Jev saw, `ChoiceAnswer` for `quality_tier`), composed into `JevAnswers` (7 fields, one per question) and `CompResult`. `CompResult`'s fields match the PRD's literal `score()` return sketch exactly (`composite`, `tier`, `gates_triggered`, `answers`) rather than also embedding `candidate`/`features`, since the PRD shows those as separate `score()` arguments, not `CompResult` members.
- `db.py`: `init_db(path) -> sqlite3.Connection` runs one `executescript` of `CREATE TABLE IF NOT EXISTS` statements for all 7 PRD tables plus two supporting indexes (`county_sales(lat, lon)` for the US-009 bounding-box prefilter, `run_results(run_id)`). `source_cache`/`jev_cache` columns are exactly as specified; `candidates` is a normalized-candidate store keyed `UNIQUE(source, source_id)` (distinct from `source_cache`'s raw-payload blobs), and `runs`/`run_results` are shaped for what US-019/US-020 will need to persist and reload a ranked run without re-scoring.
- `geo.py`: `haversine_miles` (standard great-circle formula, R=3958.7613 mi) and `acreage_ratio` (candidate/subject, `None` if either input is `None` or `0`).
- `normalize.py`: `normalize_apn(raw, county_fips, apn_length)` strips non-alphanumerics and zero-pads; takes `apn_length` as a required explicit arg rather than loading `Settings` internally, so it stays a pure function (callers pass `settings.county.apn_length`). `normalize_address` upper-cases, strips `.`/`,`, maps `#` to a `UNIT` token, and canonicalizes suffix/unit words via lookup tables. `looks_like_apn` treats any 2+-letter word as proof of a street name/suffix (i.e. not an APN); everything else composed only of digits/letters/dashes/dots/spaces, with at least one digit, counts as an APN.
- Added `tests/test_db.py`, `tests/test_geo.py`, `tests/test_normalize.py`, `tests/test_models.py` (36 tests total across the repo). The haversine test pins to the standard published Nashville->LA worked example (2887.26 km / 1794.06 mi) rather than a self-derived value, so it can't be tautological.
- All three gates green: `ruff check .`, `mypy --strict src`, `pytest -q` (36 passed).

## US-007 + US-008: county sales ingest and coordinate backfill (2026-09-30)

- `county.py`: `ingest_county` reads the sales/parcels/(centroids) CSVs, maps columns through `county.column_mapping`, and upserts into `county_sales` on `(apn, sale_date, sale_price)`. Each canonical field is read from whichever file has its mapped column (sales, then parcels; lat/lon prefer centroids), so it works whether land-use code/acreage ship on the sales or parcel extract. Rows lacking an APN, parseable date, or price are skipped and counted, because SQLite treats NULLs in a UNIQUE key as distinct and they would duplicate on every re-run. Re-ingest keeps already-geocoded coords/acreage (`COALESCE(excluded.x, x)`).
- `geocode_county` selects vacant sales lacking coords within `search.max_lookback_months` (newest first, optional `--limit`), calls `by_apn`, commits per row, fills acreage only when null, and stops on `QuotaExceeded` (exit 0, prints remaining). Other `RegridError`s exit 1 after earlier rows are saved.
- CLI: `comps ingest county` (paths default to `county.*_file` from config) and `comps ingest geocode-county`, under an `ingest` sub-app.
- Fixtures in `tests/fixtures/county/` are hand-built placeholders (20 sales, 12 vacant, 6 vacant missing coords, 4 of those in window).

## US-013 + US-014: concurrent gathering and cross-source dedup (2026-09-30)

- `gather.py`: `gather(subject, radius_mi, lookback_months, sources) -> GatherResult(candidates, source_errors, counts)` runs each `NamedSource(name, fetch)` on its own thread (`ThreadPoolExecutor`), returns candidates in source order, and logs per-source counts. A `SourceError` is recorded; any other exception is logged and recorded as a `SourceError` too, so one buggy source cannot sink the run. `build_sources(settings, conn)` builds county_sales + landwatch + realtor; without `APIFY_TOKEN` the two listing sources are still returned and fail with the runner's `SourceError`, so the gap shows up in `source_errors`.
- `db.init_db` now opens the connection with `check_same_thread=False` because worker threads share it (county reads, Apify cache). Python's sqlite3 reports threadsafety 3 (serialized).
- `dedupe.py`: `dedupe(candidates, county, apn_resolver=None)` runs three passes in PRD order (APN, coordinates within 0.05 mi and acreage within 10% of the larger, normalized address), each on the survivors of the last, so merges are transitive. `match_reason` / `is_same_parcel(a, b, county)` are the reusable pairwise predicate for the benchmark (step 14). Two records with different APNs never merge under rules 2/3. Address rule needs a leading street number (road-only addresses would merge distinct lots).
- `merge_candidates`: lead record = county source, then one with a sold price, then richest; it supplies each field, the other fills gaps. `sold_price` prefers the lead's (county's), `list_price` kept, `price` = sold price when present, status becomes sold, `sources` unioned, `raw["merged_from"]` lists (source, source_id) pairs.
- `resolve_apns(candidates, client, county)`: `by_point` for candidates with coordinates and no APN; stops at the first `RegridError` (incl. `QuotaExceeded`) and reports it in `stopped_early`. Wiring `--resolve-apn` onto `comps find` is step 12; neither `gather` nor `dedupe` is reached from a CLI command yet.

## US-015: deterministic guardrails with reason codes and auto-widen (2026-09-30)

- `guardrails.py`: `filter_candidates(subject, candidates, criteria, search, county, today)` returns `(kept, rejected)`; each `RejectedCandidate` carries every applicable reason code (`reasons`, `.reason` = the first). Codes: `is_subject` (reuses `dedupe.is_same_parcel`), `missing_price`, `nominal_price` (< floor), `excluded_deed_type` (case-insensitive), `too_far`, `acreage_out_of_band`, `stale`. A filter fires only on a fact the candidate has: no coordinates / acreage / event date (or no subject acreage) means it is kept for Jev. Bounds are inclusive with a 1e-9 slack for float rounding.
- `run_guardrails(subject, gather_fn, search, county, apn_resolver=None, today=None) -> GuardrailResult(kept, rejected, widening_steps, criteria, source_errors)`. `gather_fn(radius_mi, lookback_months)` returns a `GatherResult` (injected; step 12 closes over `gather` + `build_sources`). Every pass gathers, dedupes, filters. While survivors < `min_candidates`, `widening_plan` steps: radius x1.5 capped at `max_radius_mi` (1, 1.5, 2.25, 3.375, 5), then ONE acreage step to the wider band, then lookback += `lookback_step_months` up to `max_lookback_months`. Each step re-gathers (including the acreage step: sources ignore acreage, so it is a cache hit / repeat local read, kept uniform on purpose).
- Kept candidates first admitted by a widened pass get `widened=True` and `widen_step` (e.g. `radius:1.5mi`, `acreage:0.165-6x`, `lookback:36mo`); identity across passes is the merged-from (source, source_id) set. Candidates admitted by the initial pass are never marked. `Candidate` gained `widened` / `widen_step`.
- Config: `search.lookback_step_months` (12), `search.widened_acreage_ratio_min/max` (default: half the min, double the max). The widened band is never exceeded. `dedupe.provenance` is now public.
- Not reached from a CLI command yet: `comps find` (step 12) is the caller.

## US-016 + US-017: Jev state assembly, question set, and cached Jev client (2026-09-30)

- `state.py`: `build_state(subject, candidate, pool, today=None)` returns the PRD section 5 `subject`/`candidate`/`comparison` dict. None/empty fields are omitted (a `False` boolean is kept), descriptions are cut to 1,500 chars, `comparison.price_per_acre_vs_pool_median` uses the median over *sold* pool candidates and is omitted below 3. `Candidate` has no zoning or ZIP field, so candidate zoning is read from `raw["zoning"]` and candidate ZIP from a trailing 5-digit ZIP in `address`; `same_zoning`/`same_zip` are omitted when either side is unknown (today no normalizer sets `raw["zoning"]`, so `same_zoning` is usually absent). `Parcel` has no road access/utilities/description, so the subject block carries only apn, address, acreage, zoning, land_use.
- `questions.py`: the 7 questions as plain `QuestionSpec` data, independent of the SDK. `questions_json()` feeds the cache key.
- `jev.py`: `JevJudge(transport, conn, model="jev-latest", sleep=time.sleep)` with `judge`, `judge_with_usage`, `judge_many(states, concurrency=8)`. `JevTransport` protocol keeps `typesafe-sdk` (pinned `==0.7.1`) behind `TypeSafeTransport`, which turns SDK retries off so the judge's backoff (1s doubling, cap 30s, honors Retry-After, 5 tries) is the only layer. Retried: 408/429/5xx (529 included) and connection errors; 401/422/other 4xx raise `JevFatalError` at once. Tries exhausted raise `JevUnavailableError`; `judge_many` returns that error in the slot for that state and raises only fatal errors.
- `jev_cache` stores `JevAnswers` JSON plus the input tokens Jev reported; a cache hit returns the stored tokens with `cached=True` (not billed).
- SDK Noul answers carry only a probability, so `NoulAnswer.confidence` is derived as `|2p - 1|`. `ScoreAnswer.score` changed from int to float because Jev returns an expected level (e.g. 1.7); rounding would lose information the scorer can use.
- `JevJudge.from_settings(settings, conn)` builds the real client from `TYPESAFE_API_KEY`. Nothing calls `build_state`/`JevJudge` until `comps find` (US-019).

## US-018: composite scoring, hard gates, tier demotion, and ranking (2026-09-30)

- `scoring.py`: `score(candidate, answers, features, config: Settings) -> CompResult` implements the section 5 formula with `scoring.w1..w7`. Similarity scores are divided by 3; recency = `1 - months/search.lookback_months` and proximity = `1 - distance/search.max_radius_mi`, both clamped to [0, 1]. A feature that is None (no coordinates / no event date) contributes 0. Composite is not clamped (weights are not forced to sum to 1).
- `Features(distance_miles, months_since_event)` is the pydantic feature record (JSON-storable for `comps rescore`); `compute_features(subject, candidate, today)` builds it (step 12 calls it and persists it next to the answers).
- Gates: `arms_length < scoring.arms_length_min` (0.5) forces `reject`; `red_flags > scoring.red_flags_max` (0.7) rejects (policy `reject`, gate `red_flags_reject`) or only adds the `red_flag` marker (policy `warn`). Both thresholds are new config keys with those defaults; comparisons are strict.
- Demotion: from `quality_tier.choice`, ONE level when composite < that choice's floor or `quality_tier.confidence < min_confidence`. Both triggering still demotes once (conservative reading); both reasons are recorded (`below_tier_floor`, `low_tier_confidence`). `reject` has no floor and never demotes; a forced reject skips demotion. `gates_triggered` therefore holds gates, the warn marker, and demotion reasons.
- `rank(results: Sequence[ScoredComp])` sorts by tier, composite desc (rounded to 9 places so float noise is not a tie), then sold before active/pending; stable. `ScoredComp(candidate, result)` exists because `CompResult` does not carry status.
- Not reached from a CLI command yet: `comps find` (step 12 / US-019) and `comps rescore` are the callers.

## US-019: `comps find` end-to-end command (2026-09-30)

- `pipeline.py`: `run_find(target, settings, conn, clients, radius_mi=, resolve_apn=, today=, now=) -> RunReport` is the one pipeline function (`bench run` will call it too): `resolve_subject` -> `run_guardrails` (gather + dedupe + filter + auto-widen, `gather_fn` closes over `gather` and the injected sources) -> `compute_features` / `build_state` -> `judge_many` -> `score` -> `rank` -> `save_run`. All clients arrive in `FindClients(regrid, sources, judge, apify_items_fetched)`; the CLI hook is `cli.find_clients_factory` (default builds live Regrid, `build_sources`, `JevJudge.from_settings`; the Jev key is checked before any paid call). `SubjectNotFoundError` -> exit 2; `InvalidRadiusError`, `RegridError`, `JevError` -> exit 1.
- `--radius R` becomes `search.initial_radius_mi` (auto-widen can still grow it, never past `max_radius_mi`); `effective_search` rejects R <= 0 or R > max before any client is built.
- Judged = kept by guardrails and answered by Jev. A candidate whose Jev retries ran out is listed under "Unjudged" in the report and has no `run_results` row; a fatal Jev error aborts the run before anything is saved.
- Cost: Jev tokens from non-cached `JudgedAnswers` x `JEV_INPUT_USD_PER_MTOK` (0.042); Apify items = delta of the new `ApifyRunner.items_fetched` (live items only, cache hits are free); Regrid records = delta of `RegridClient.records_used()` (any lookup client with `records_used()` is metered; others report 0).
- `report.py`: `RunSummary` / `RankedComp` / `RunReport`, `render_report` (header: subject, search window, widening, source errors; Sold and Listing sections sharing one global rank; footer: gathered / deduped / filtered (by reason) / judged and cost), `select_comps` (`--top`, `--include-rejects`; rejects are reject-tier comps, guardrail drops are counted by reason in the footer), `write_export` (JSON: `run` summary plus per comp the candidate, provenance (source, source_id), all source URLs, features, and the full `CompResult` with raw Jev answers; CSV: the table columns, `;`-joined sources/flags). The export contains exactly the comps displayed.
- `runs.py`: `save_run` writes one transaction. `runs.params_json` = full `RunSummary`; each `run_results` row = composite/tier/gates/`answers_json` plus `features_json` = `{"features", "state", "candidate"}`. Step 13's `rescore` should rebuild from the `candidate` snapshot in `features_json` (the shared `candidates` row is refreshed by later runs) and re-run `score`, `rank`, `render_report`. No schema change was needed.
- `dedupe.merge_candidates` now also records `raw["urls"]` (every source URL), read via `source_urls`, so provenance URLs survive a merge.
- `comps subject` now goes through the shared `resolve_subject`.

## US-020 + US-021: `comps rescore` and `comps bench import` (2026-09-30)

- `runs.load_run(conn, run_id) -> (RunSummary, list[StoredResult])` decodes a saved run (candidate snapshot, answers, features, state) in original rank order; `RunNotFoundError` for an unknown ID, `StoredRunError` for rows saved without detail.
- `rescore.rescore_run(conn, settings, run_id) -> RunReport` re-runs `score` + `rank` with the current `scoring` config (recency/proximity also use the current `search.lookback_months` / `max_radius_mi`). It takes no clients and writes nothing; `comps rescore <run_id> [--top --include-rejects --out]` prints through `render_report`, so the header/counts/cost are the original run's. Unknown run or missing DB file exits 1 (the DB is not created).
- `bench.import_benchmark(conn, settings, csv)`: normalizes `comp_apn` (`normalize_apn`), `comp_address` and `subject_id` (APN-like -> `normalize_apn`, else `normalize_address`, so subject keys match what `find` resolves). Skipped with a line number and reason: no subject, neither APN nor address, `comp_status` not sold/active, bad price (non-numeric/non-finite), bad date (non-ISO). Price, date and `crm_rating` may be blank. Re-import deletes and re-inserts every subject that has >=1 valid row in the file; other subjects are untouched. Table `benchmark_comps` is in the idempotent schema.
- `tests/fixtures/benchmark/crm_comps.csv`: 2 subjects x 4 comps plus one row (line 10) with no identifiers.
- Step 14 (`bench run`) reads `benchmark_comps.subject_id` (normalized) to pick subjects; APN subjects are zero-padded APNs, address subjects are normalized addresses.

## US-022: `comps bench run` (2026-09-30)

- `bench_run.py`: `run_benchmark(conn, settings, pipeline, reports_dir, now=None) -> BenchResult` runs `pipeline(subject_id)` (a `Callable[[str], RunReport]`; the CLI passes `run_find` bound to one shared `FindClients`, so provider caches apply) for every subject in `benchmark_comps`, then writes `bench_<ts>.md` and `review_<ts>.csv` (same UTC timestamp; opened with `"x"`, never overwrites) under `reports_dir` (CLI `--reports-dir`, default `reports/`, gitignored).
- `RunReport` gained `rejected` (guardrail drops with reason codes) and `unjudged_candidates`, set by `run_find` only (empty after `rescore`). Together with the judged `comps` they are the whole deduped pool the benchmark matches against.
- Matching = `dedupe.is_same_parcel` (APN, coordinate, address) between the CRM comp (identifiers only, so in practice APN or address) and each pool entry; first match wins.
- Metrics: recall = CRM comps in pool / CRM comps (target 70%); agreement = CRM comps tiered excellent/good / CRM comps in pool (target 60%; filtered and unjudged comps count as in-pool, never agreeing); filter loss = dropped by guardrails / CRM comps; overlap@5 = our top 5 (rejects excluded) that are CRM comps / min(5, CRM comps). Overall pools counts across subjects that ran. Reviewed precision is printed as PENDING.
- Review CSV columns: `subject_id, category, detail, apn, address, status, price, date, our_rank, our_tier, composite, crm_rating, human_label` (blank). `category` = `crm_only` (not in pool / guardrail reason / unjudged), `ours_only` (top-5 not a CRM comp), `tier_conflict` (CRM comp we tier marginal/reject). Step 15 (`score-review`) reads this file and appends to the bench report with the same timestamp.
- A subject whose pipeline raises (any exception) is listed under "Failed subjects" in the markdown, excluded from metrics, and does not stop the batch. CLI exits 1 if no subject ran (reports still written) or on setup errors (missing DB, no imported comps, client factory failure).
- Subject targets are the normalized ids stored by import (zero-padded APN or upper-cased address), passed straight to `run_find`.

## US-023: `comps bench score-review` (2026-09-30)

- `bench_review.py`: `score_review(review_csv, now=None) -> ReviewScoreResult` finds `bench_<ts>.md` beside `review_<ts>.csv` (file name must match `review_YYYYMMDD-HHMMSS.csv`), tallies `human_label` (case/space-insensitive good/bad, blank = unlabeled; any other value or an unknown category fails with line numbers before the report is touched) and appends a `## Reviewed precision results` section. A previously appended section is replaced, so re-scoring after more labeling is safe.
- Agreements are not rows in the review CSV, so the bench report now has a "Review inputs" section (`bench_run.TOP5_AGREEMENTS_LABEL` / `CRM_AGREEMENTS_LABEL` lines: overall top-5 hits and CRM comps tiered excellent/good) that `score-review` parses. Bench reports written before this step lack it and fail with a message to re-run `bench run`.
- Precision = (top-5 CRM agreements + `ours_only` labeled good) / (agreements + labeled `ours_only`). Bad share = (`crm_only`/`tier_conflict` labeled bad) / (CRM comps we tier excellent/good + labeled CRM rows). Unlabeled rows are excluded from both denominators and reported (by group); any unlabeled row marks the verdict "(provisional)". No labeled top-5 comps gives n/a, not a pass.
- A marginal-tier top-5 hit that is also a `tier_conflict` row counts as an agreement for precision (the CRM lists it) and its label only feeds the CRM bad share.
- CLI: `comps bench score-review <review.csv>` prints the two ratios, the verdict and the unlabeled count; missing review/bench file or bad labels exit 1. Tests import fixtures from `test_bench_run` (pytest rootdir mode, no `tests` package).
