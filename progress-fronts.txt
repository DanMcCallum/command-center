## Iteration 1 - US-006: what's-next pass
- `workers/fronts/whats-next-prompt.md` (rules: ask instead of guessing, two questions, never touch the north star, honour Boundaries, read Answers first, keep now.md to a screen) and `workers/fronts/whats-next.sh <slug> [memory-file ...]`: opus structured call with `--tools Read,Grep,Glob` from the project root, prompt = rules + north star + old now.md + the sessions that just ended + up to 5 earlier memory files for the front.
- now.md is composed in bash: title, `## Last session` (from the newest given memory file), `## Yesterday` (memory files dated yesterday for this front), the model's four sections (any Last session / Yesterday / Answers sections it produced are stripped), then the preserved `## Answers from Daniel`.
- Suggestions (kind task, body = prompt, type/model/slashCommand) and questions (kind question, body = why it matters) are posted in one batch with sourceSessionId / sourceMemoryFile. On model failure now.md is untouched and a "What's-next failed for <slug>" question is posted; exit 2.
- Coalescing: per-front `flock` on `workers/fronts/locks/<slug>.lock`; a run that finds it held appends its files to `<slug>.pending` and exits 0; the holder drains the pending list with one more pass before exiting. (Deviation from the PRD's 20-minute window: lock-based coalescing needs no later trigger and never delays an update.) The "spawn a subagent" instruction became "read more memory files under fronts/memory/ if it would change your answer", since Read/Grep/Glob cover it.
- Harness now at 37 checks. A stub run produced the expected now.md layout.
