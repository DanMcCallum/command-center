# Progress — ad-photos feature (specs/ad-photos.md)

## Iteration 1 - US-001: Photo upload API endpoint
- Implemented `POST /api/tasks/[id]/photos`: multipart upload of one photo into
  `workers/workspace/outputs/<taskId>/photos/`, with 404 for unknown tasks and
  400 for bad filename pattern, traversal, disallowed extension, and >15 MB.
- Files changed:
  - dashboard/app/api/tasks/[id]/photos/route.ts (new)
  - specs/ad-photos.md (checked off US-001)
- Verified with curl against `npx next dev -p 3001` (temp task created and
  DELETEd afterwards): valid upload → 200 + file on disk; bad ext / oversize /
  traversal / bad pattern → 400; unknown task → 404. `npx tsc --noEmit` clean.
- Learnings for future iterations:
  - Path resolution pattern for reaching workers/ from dashboard route
    handlers: `path.resolve(process.cwd(), '..')` (same as files/[...path] and
    posting-auth routes). config/paths.json is NOT read by the dashboard.
  - Filename policy chosen: REJECT (400) anything containing `/`, `\`, or `..`
    rather than silently basename-sanitizing — the spec's curl checklist
    expects an error status for traversal filenames. Note `00_..jpg` also gets
    rejected (contains `..`) even though it matches the regex.
  - App Router route handlers have no body-size limit config; `request.formData()`
    handled the 15 MB+ test file fine — no route config needed.
  - Dev-server workflow: start `npx next dev -p 3001` in background with pid
    file, poll `/api/tasks` until up (~10 s), kill by pid when done. Port 3000
    serves stale production code — never verify against it.
  - The `file` form part arrives as a web `File`; write with
    `Buffer.from(await file.arrayBuffer())`.
  - US-002/003 (PhotoPicker) should generate the `NN_` prefix client-side at
    submit time; the API only validates it.

## Iteration 2 - US-002: Photo picker on the Ad Builder form
- Implemented `dashboard/components/PhotoPicker.tsx`: hidden file input
  (accept jpeg/png/webp/gif, multiple) behind an "Add photos" button,
  thumbnail grid from object URLs (revoked on remove + unmount), filename +
  × button per thumbnail, selection-time rejection messages (bad extension,
  >15 MB) naming file and reason, amber "At least 1 photo is required." hint
  when empty. Component owns state, reports `PickedPhoto[]` ({id, file, url})
  to the parent via onChange.
- Ad Builder page: renders the picker between Platforms and the submit row,
  disables submit while `photos.length === 0` (plus a belt-and-suspenders
  check in submit()). No upload logic yet — that's US-004.
- Files changed:
  - dashboard/components/PhotoPicker.tsx (new)
  - dashboard/app/ad-builder/page.tsx
  - specs/ad-photos.md (checked off US-002)
- Verified: `npx tsc --noEmit` clean; browser verification via a headless
  Playwright script (chromium from workers/posting/node_modules) driving
  `npx next dev -p 3001` — 15 checks incl. initial disabled state, mixed
  valid/bad/oversize selection, remove, re-add-same-file, no page errors.
  Screenshot inspected: matches the dark-minimalism design.
- Learnings for future iterations:
  - Browser verification pattern: write a temp .mjs INSIDE workers/posting/
    (ESM resolves 'playwright' relative to the script file, not cwd), launch
    chromium headless, drive localhost:3001, delete the script after.
    setInputFiles bypasses the accept filter — good for testing rejection.
  - First Playwright run right after dev-server start can flake on the
    route's first compile; re-run before diagnosing a real failure.
  - Don't wrap PhotoPicker in the page's <Field> helper — it's a <label>,
    which would forward clicks anywhere in the section to the picker's
    buttons (and nest labels invalidly). Used a plain div with the same
    header styling.
  - Reset input.value after handling selection so re-picking the same file
    fires change again.
  - PickedPhoto has a stable per-item `id` — use it as the drag key for
    US-003 instead of array index.
