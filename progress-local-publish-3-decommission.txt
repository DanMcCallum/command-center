## Iteration 2 - US-002: Publish buttons respect agent liveness
- Implemented agent liveness surfacing on the tasks page:
  - New `dashboard/lib/agent-liveness.ts`: `useAgentLiveness()` client hook returning `{online: boolean|null, lastSeenAt}` (null = first fetch not yet resolved). ONE shared module-level poller (subscriber set + refcounted setInterval) no matter how many components mount it. Polls GET /api/agent-status every 15s; online = lastSeenAt within ONLINE_WINDOW_MS = 45_000 (3x the agent's DEFAULT 15s poll — AGENT_POLL_SECONDS is operator-tunable but the server can't see it, so the window is fixed). On fetch failure it recomputes from the last known lastSeenAt so a stale "online" ages out.
  - `dashboard/app/tasks/page.tsx`: header dot indicator "Poster agent online/offline" (teal #4DAB9A / amber #D4A04D dot), tooltip shows last-seen time; hidden until first fetch resolves (online === null).
  - `dashboard/components/PublishButtons.tsx`: when offline, buttons go amber with ring + title tooltip and an amber warning line renders: "Poster agent offline — start it on your machine. Publishing still queues the job for when it comes back." Buttons stay clickable — publish still queues.
- Files changed: dashboard/lib/agent-liveness.ts (new), dashboard/app/tasks/page.tsx, dashboard/components/PublishButtons.tsx, workers/posting/verify-agent-liveness.ts (new, committed harness), specs/local-publish-3-decommission.md.
- Verified: dashboard `npx tsc --noEmit` clean; workers/posting `npm run typecheck` clean; Playwright harness (verify-agent-liveness.ts) all 6 checks pass — offline indicator, warning text, tooltip, publish-POST-still-fires, online indicator, no-warning-when-online.
- Learnings for future iterations:
  - page.route fixtures for /api/tasks + /api/agent-status give full control of liveness states without touching agent-status.json or tasks.json; POST-capture via a route that flips a boolean verifies "clicking still queues" with zero server writes.
